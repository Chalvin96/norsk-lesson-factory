# Security policy

## Supported versions

The latest tagged release and the repository's default branch are supported. A fix is
released as a new version tag when the issue affects published lesson data or
the authoring pipeline. Older tags are not maintained; upgrade before
reporting a problem that reproduces only on an obsolete release.

## Reporting a vulnerability

Please report vulnerabilities privately through the repository's GitHub
**Security → Advisories → Report a vulnerability** flow. Do not open a public
issue or include exploit details in a pull request. If private reporting is
unavailable, contact the repository maintainers through the GitHub profile and
request a private channel, including the affected tag or commit, impact,
reproduction steps, and any suggested mitigation.

We acknowledge reports within five business days, provide a severity and
remediation assessment within ten business days, and coordinate disclosure
after a fix or mitigation is available. Do not include learner data, provider
credentials, or other secrets in a report.

Temporary exceptions to an automated security finding must be recorded in the
pull request with an owner, rationale, affected dependency or workflow, and an
expiry date no later than 30 days out. Exceptions do not waive a known
actively exploited issue.
